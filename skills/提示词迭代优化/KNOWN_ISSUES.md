## F. 元教训（写给未来的我）

1. **自己写的仪器只证明自己想验的东西**——必须主动构造反例打自己的工具（A1 就是这么发现的）。
2. **规则引擎抓不住语义矛盾**：结构分 96 与垃圾稿同分。
3. **"提醒型"文字挡不住复发**，只有退出码能挡。
4. **用户看不见 = 没发生**：过程必须播报，断言必须可复现。
5. 本技能的正确用法：规则引擎当下限 → 门禁防退步 → 子代理盲评当第二双眼睛 → **真实用例做最终验收**。缺哪层，那层的洞就漏过去——本场每层各抓过一次，也各漏过一次。
6. **分数下降先怀疑仪器，不要先改稿**。2026-10-07 两次 96→76 / 70→26 都是规则器假阳性（A7/A8），改稿只会毁掉已经正确的内容。判据：分数暴跌而内容明显变好 = 仪器错。
7. **盲评的边际收益递减，且会自我膨胀**：同一命题 4 次盲评分别抓出 5 / 2 / 1 / 0 条 blocking_conflicts。第 3 次起必须给 judge 划定"什么不算阻塞"，否则永远收敛不了（E8）。
8. **PASS 不等于验过了**：G9 因为正则只认 ASCII，本次 7 轮的"变量完整 PASS"全是假 PASS（A9）。**看到门禁全绿时，先问一句"这个检查真的跑了没有"**——空转的检查比没有检查更危险，它会给人虚假的安全感。
9. **KNOWN_ISSUES 自己也会过期**：A1 记的"反例实测 exit 0"在 2026-10-07 复审时已变成 exit 1（被 G5/G6/G7 拦下）。**清单里的"证据"要定期重跑，不能当永久事实引用**——这和 F.1 是同一件事，只是对象换成了这份文档本身。
