# LangGPT 改写骨架

把任意任务型提示词改写为如下结构。**只输出结构化提示词本身，不要额外解释。**
按需删减 / 增补节（如加 `## Variables`、`## Output Format`、`## Examples`、`## Tone`）。

```markdown
# Role: <一句话角色>

## Profile
- 身份：<领域 + 资深程度>
- 版本：v2
- 依据：<用户原始意图原文或链接>

## Skills
1. <核心能力一>
2. <核心能力二>
3. <核心能力三>

## Goals
- <首要目标，对应原始诉求>
- <次要目标>

## Workflow
1. <第一步：澄清/确认目标与约束>
2. <第二步：拆解可执行步骤>
3. <第三步：执行并产出中间结果>
4. <第四步：汇总最终结果，标注假设>

## Constraints
- <边界：不做什么>
- <格式：输出必须遵循的结构>
- <质量：具体、可量化，避免模糊表述>
- <禁忌：明确禁止的行为/内容>

## Initialization
作为 <Role>，依据上述设定开始执行用户请求。
```

## 使用要点

- **角色具体化**：避免"助手/专家"泛称，写清"资深 X 领域执行者"。
- **约束可校验**：约束写成可判断的真假句（"输出必须是 JSON，含字段 a/b/c"），而非"尽量好"。
- **工作流可操作**：每步是动作 + 产出，而非形容词。
- **变量化复用**：若提示词要在多场景复用，把易变部分抽成 `## Variables`：
  `商品={{product}}、报价={{price}}、底线={{floor}}`，调用时注入。
- **给示例**：复杂输出格式务必配 `## Examples` 一个正例，显著降低跑题率。
- **少即是多**：不是每节都必填；缺哪补哪，不要为结构而结构。

## 常见反模式（改写时要消除）

| 反模式 | 改法 |
|--------|------|
| "写一些关于 X 的内容，尽量吸引人" | 明确载体（帖子/邮件/脚本）、平台、指标（点击率/转化）、受众 |
| "你是一个有帮助的助手" | 具体到领域与资历，并给 Skills |
| 只有目标没有步骤 | 补 `## Workflow` 有序步骤 |
| 语气模糊（"友好一点"） | 改为可观测约束（"用第二人称、句长≤20 字、不用感叹号"） |
| 无输出格式 | 补 `## Output Format` 或 `## Examples` |
